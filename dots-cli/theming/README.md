# theming/

The theming engine, the per-app adapters and the accent table. Everything
theming-related lives here; callers (the `dots theme` CLI in
`../lib/theme.sh`, future setup scripts) only resolve a theme name and invoke
`apply-theme.sh`.

```
theming/
├── apply-theme.sh   # the engine: wal + accent + adapters + notify — owns the code
├── accents          # main accent per theme — single source of truth
├── adapters/        # one script per app that must react to a theme change
│   ├── ghostty.sh
│   ├── hyprland.sh
│   ├── pi.sh
│   ├── quickshell.sh
│   ├── starship.sh
│   ├── walker.sh
│   └── yazi.sh
└── README.md
```

## The idea

`dots theme <name>` restyles the whole desktop. There are exactly **two
sources of truth**, and every app gets its colors from one of them — never
from a hex value in its own config:

1. **The wal scheme** (`~/.cache/wal/`) — background, foreground, cursor and
   the 16 colors `color0`–`color15`, generated by pywal16 from a built-in
   theme.
2. **The main accent** (`~/.cache/wal/accent`, one `#rrggbb` line) — a color
   wal doesn't have, chosen per theme in `accents`. Each line is
   `<theme-name> <#rrggbb | colorN>`; `colorN` is a slot of that theme's wal
   scheme. Themes without a line use `default`. This lets the user keep a
   personal accent (e.g. `#f6aede` for dracula) while it still changes with
   the theme.

**Rule for app configs:** use wal colors or the accent, never hard-coded hex.
Terminal apps (yazi, herdr, …) use the named ANSI colors (`magenta`,
`darkgray`, …) — those are wal's slots because ghostty takes its palette from
wal. The only exception is generated files (adapters may write hex).

## Flow of `apply-theme.sh [-l] <theme-name>`

1. `wal [-l] --theme <name>` regenerates `~/.cache/wal` and renders
   `~/.config/wal/templates/` (stowed from `stow/wal/`).
2. Resolve the accent: the theme's line in `accents`, else `default`, else
   `color5`; `colorN` is read from `~/.cache/wal/colors.sh`. Written to
   `~/.cache/wal/accent`. Fails the run if it isn't a valid `#rrggbb`.
3. Every **executable** `adapters/*.sh` runs in sorted order with the theme
   name as `$1` (the cache and the accent are already fresh). Output goes to a
   temp log; a failed adapter is a warning, the rest still run; any failure
   fails the script.
4. `notify-send` summary.

`dots theme` (`../lib/theme.sh`) adds `-l` on its own for light-only themes
(e.g. `catppuccin-latte`); themes that exist as both (e.g. `solarized`) stay
dark unless `-l` is given. Both variants share one line in `accents`.

| hyprland | template `colors-hyprland.conf`, parsed by `shared.lua` | `shared.lua` reads `~/.cache/wal/accent` → global `accent` (active border) | `hyprland.sh`: `hyprctl reload` |

| hyprlock | — | via quickshell: `~/.cache/quickshell-theme/hyprlock.conf` (`$qs_accent`) | — |
| yazi | preset theme = ANSI colors → via ghostty | generated `wal` flavor (`theme.toml` selects it) | `yazi.sh`: renders `~/.cache/wal/yazi-flavor/flavor.toml`, links it to `~/.config/yazi/flavors/wal.yazi` |
| pi | generated `wal` theme (`settings.json` selects it): wal colors as hex, tinted backgrounds blended over the wal bg | accent, title/heading/border colors | `pi.sh`: renders `$PI_CODING_AGENT_DIR/themes/wal.json` (real dir, not stowed → never in the repo); pi hot-reloads it, no restart |
| herdr | `theme.name = "terminal"` = ANSI colors → via ghostty | **none on purpose** — herdr can't read files, only hex/named colors in `config.toml` | — (follows ghostty) |
| shell / fzf | `.commonshellrc` sources `colors.sh` | — | — |
| starship | named ANSI colors in `stow/tools/.config/starship.toml` | `accent` from a `[palettes.wal]` table | `starship.sh`: renders `~/.cache/wal/starship.toml` (`palette = "wal"` + base + palette); `.commonshellrc` sets `STARSHIP_CONFIG` to it. Applies on the next prompt |
| walker | generated `wal` theme (`config.toml` selects it): the packaged default `style.css` with its five `@define-color` lines set to wal bg/fg/color1 | `accent_bg_color` | `walker.sh`: renders `~/.cache/wal/walker-theme/`, links it to `~/.config/walker/themes/wal`, restarts the service via hyprland |

quickshell's `config/overrides.json` still exists for `highlight` (`"colorN"`
→ wal slot, hex → fixed). `mainAccent` is no longer an override.

## Adding an app

1. Can it follow the terminal palette (named ANSI colors)? Then it's done —
   no adapter, no template.
2. Does it read a file? Point it at `~/.cache/wal/*` or a new wal template in
   `stow/wal/.config/wal/templates/`, and at `~/.cache/wal/accent` if it needs
   the accent.
3. Only if it must be told to reload, or its config can't reference a file,
   add `adapters/<app>.sh` (contract below).
4. Update the table above.

## Adapter contract

- File name: `<app>.sh`, executable, run in sorted order.
- Invocation: `adapter.sh <theme-name>`; `~/.cache/wal` and
  `~/.cache/wal/accent` are already fresh when the adapter runs.
- Exit 0 if the app isn't installed/running — adapters must be no-ops on
  machines that don't run the app.
- The directory listing is the registry (same filesystem-as-state pattern as
  `packages/` and `stow/`). **Enable**: `chmod +x`. **Disable**: `chmod -x`.

## Gotchas

- **Hyprland reload re-reads modules only because `hyprland.lua` clears
  `package.loaded`** before each `require` — the Lua state survives
  `hyprctl reload`.
- **yazi only applies flavors in a real terminal.** It picks the dark/light
  flavor from the terminal's reported background; under `script` (no
  terminal answering) the flavor is silently skipped. Test in ghostty.
  Running yazi instances only pick up a new accent on restart.
- **herdr has no row-text color**, so a strong `active_row_bg` (e.g. the
  accent) makes the light text unreadable — it uses `darkgray` (color8).
- **`quickshell.sh` can leave extra instances** (multiple bars): `qs kill`
  without a selector ends only one instance; if a stray one exists, every
  run leaves one behind. Fix: kill every pid from `qs list --all`. Until
  then, clean up with `qs kill --pid <pid>` per instance and `qs -d`.

## Testing without touching the real colorscheme

```
WAL_BIN=echo dots-cli/theming/apply-theme.sh some-theme
```

`WAL_BIN` stubs wal. The accent is still resolved (from the *current*
cache) and the adapters still run — so this does change the live accent;
re-apply your theme afterwards.
