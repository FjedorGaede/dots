## Writing Principles

| Principle | Bad | Good |
|-----------|-----|------|
| **Step-by-step numbered procedures** | "Parse the PDF using PyPDF2, handling page ranges and errors." | "1. Run `./scripts/parse-pdf.py <file>`. 2. Check `success` in the output. 3. If false, read stderr." |
| **Third-person imperative** | "You should extract the text from the PDF." | "Extract the text from the PDF." |
| **Concrete over abstract** | "Output is a JSON with status, path, pages, content." | "Output: `{"success": true, "file_path": "...", "total_pages": 5, "pages": [{"page": 1, "text": "..."}]}`" |
| **Consistent terminology** | Sometimes "parse", sometimes "extract", sometimes "read". | Always use "extract" for getting text from PDFs. |
| **Execution over instruction** | "Construct a curl command with the right headers." | "Run `./scripts/api-call.sh <endpoint> <params>`." |

## When to Add Scripts

Add scripts when:
- Operation is deterministic (validation, formatting, parsing)
- Same code would be generated by the agent repeatedly
- Errors need explicit handling

Scripts save tokens and improve reliability.

## When to Split Files

Split into separate files when:
- SKILL.md exceeds 100 lines
- Content covers distinct domains
- Advanced features are rarely needed

## Naming Rules

- 1-64 characters
- Lowercase `a-z`, digits `0-9`, single hyphens `-`
- No leading/trailing hyphens, no consecutive hyphens
- Pi does NOT require the name to match the parent directory

Valid: `pdf-tools`, `code-review`, `data-analysis`
Invalid: `PDF-Tools`, `-pdf`, `pdf--tools`
